# UI Anatomy Scanner（プロトタイプ）

UI の画面を入力すると、構成・原則・視線・見え方を一画面で確認できる分析ツールです。右パネルの6つのタブで構成されます。

1. **構成要素**: ボタン（主・副・テキスト・アイコン）、バナー、ナビゲーション、フォーム、カードなどの種類・数・位置
2. **10原則**: ニールセンの10ヒューリスティクスの指摘。根拠・重大度（0〜4）・改善案つき。補助として WCAG 由来のチェックも表示
3. **仮想視線**: ペルソナとタスクを選ぶと、想定される視線の順路・滞留・ヒートマップ・見落とされやすい要素を表示
4. **Age Lens**: 年齢・視覚特性のフィルタ（ぼやけ・コントラスト感度の低下・水晶体の黄変・視野狭窄・色覚特性）を画面に重ね、通常表示と左右で比較。レンズ適用後の見え方で「読みにくい文字」「押しにくい操作領域」「視野の外にある主要要素」「色の区別がつきにくくなるボタンの組み合わせ」を判定
5. **比較（Before/After）**: 解析結果を「Before」として保存し、別の画面（After）と同じ基準で比較。10原則スコアのレーダー重ね合わせ、解消・新規・変化した指摘、構成要素・Age Lens・仮想視線の差分、ステージ上の左右ワイプ、Markdown レポート
6. **ペルソナ**: 複数ペルソナの並列比較（ワイヤーフレーム上の軌跡・指標・要素×ペルソナの到達率マトリクス・自動所見）と、**ペルソナの自作**（視線の重み・ふるまい・視覚特性を保存）

`index.html` を開くだけで動きます（単一HTML・ビルド不要）。

## 使い方

- **サンプル**: 架空の4サイト（EC／社内申請フォーム／SaaSランディング／ECの改善版）。弱点を意図的に仕込んであります。「Before/After デモ」で比較の流れを確認できます
- **HTML貼り付け**: ページのソースを貼ると解析します
- **URL**: ブラウザからは他サイトのHTMLを直接取得できない（CORS）ことが多いため、自前の中継を指定します（下記）

## 重要な制約（誤解を避けるために）

- 指摘は**ルールベースの推定**で、実ユーザーテストの代替ではありません。一次レビューを速くするための道具です
- 視線は**実測ではなく仮想**です。要素の目立ち・タスクとの関連・位置の傾向と、ペルソナごとの仮定から確率的に生成します（シード固定で再現可能）
- スクリプトは実行しません（sandbox の iframe に HTML/CSS のみ描画）。JavaScript で描画されるサイトは、中身が少なく解析されることがあります
- ニールセン10項目のうち機械的に判定できるものだけ自動指摘し、判断が必要な項目は「要確認」として人が判定します

## 自動判定の対応表

| 原則 | 自動で見ているもの |
|---|---|
| H1 状態の視認性 | ステップ/ナビの現在地の有無と、強調の視覚差 |
| H2 実世界との一致 | 曖昧なリンク文言、英語混在、同じ概念の呼び方の揺れ |
| H3 主導権と自由 | モーダルの閉じる手段、自動再生、カルーセルの停止、フォームの戻る導線 |
| H4 一貫性 | ボタンの見た目の種類数、角丸、フォント数、見出しサイズ |
| H5 エラー予防 | 破壊的操作と主要操作の近接、入力欄のtype |
| H6 認識>想起 | ラベルなしアイコン、プレースホルダのみの入力欄 |
| H7 柔軟性 | 検索の有無、autocomplete |
| H8 最小限のデザイン | ファーストビューのバナー数・主要ボタンの競合・操作要素の数 |
| H9 エラー回復 | エラー表示領域の有無 |
| H10 ヘルプ | ヘルプ/問い合わせ導線の有無 |
| 補助 | コントラスト比、小さな文字、操作領域の大きさ、alt |

## ペルソナの自作

「⑥ ペルソナ」→「作る・編集する」で作成します。

- **視線のふるまい**: 視覚的な目立ち／タスク関連／位置の傾向の重み、注視の回数と長さ、視線の移動距離、見返しやすさ、本文を読む傾向、バナーへの反応
- **視覚特性**: ④ Age Lens と同じ指標（ぼやけ・コントラスト感度・黄変・視野狭窄・色覚）。プリセットからのコピーや、④の現在の設定の取り込みもできる。視覚特性があるペルソナは、読めない文字の要素が注視されにくくなる
- 標準の4ペルソナは編集できず、選ぶと「コピー」として編集できます。自作は最大6件
- 保存先はこのブラウザの localStorage です（端末をまたいで共有されません）。JSON で書き出し・読み込みができるので、バックアップや別端末への移行はこちらを使います
- 比較に含めるペルソナは、「比較する」画面のチップで切り替えます

## 比較機能の注意

- **Before/After**: 指摘は、件数などの数字を除いたタイトル＋原則で同一とみなします（「ボタンの見た目が8種類」→「3種類」は『変化』）。仮想視線は、両方の画面を同じペルソナ・タスク・乱数列で動かした差で、Age Lens の視線への反映は使いません。差はルールベースの指標上の変化で、実際に良くなったかはユーザーテストで確認が必要です
- **ペルソナ並列比較**: 各ペルソナは、そのペルソナ自身の重みで動かします（③のスライダーの値は使いません）。30試行は同じ乱数列なので、同じ設定なら同じ結果になります。差は仮定の差から生まれる仮想の結果で、実ユーザーの行動を保証しません

## Age Lens の仕組みと注意

- 見た目: 解析対象をもう1枚描画し、CSS/SVGフィルタ（blur・contrast・色覚は Machado et al. 2009 の行列・黄変は青成分の減衰）を重ねて、左右で比較します
- 判定: 同じ変換を文字色・背景色に当ててコントラスト比を再計算し、WCAG の基準（通常文字4.5:1／大きな文字3:1）で判定します。ぼやけは文字サイズの約18%超で「重大」、約12%超で「注意」（経験則の目安・未検証）
- プリセット（65歳前後・白内障・緑内障など）の数値は**説明用の目安**です。医学的な再現や診断ではなく、実際の見え方は個人差が大きいです
- 背景が画像・グラデーションの文字は、背景色を一意に決められないため判定対象外（件数のみ表示）です

## ツール自体のデザイン方針（固定スペック）

「AI が作った感」を避けるため、「ほしい雰囲気」と「避けたい表現」をセットで固定しています。考え方は、Fyve「[AIで作る図解のAI感を消す方法｜プロンプト設計](https://fyve.co.jp/ai-advisor/articles/ai-diagram-remove-ai-look)」（2026/07/25）を参考にしました。ただし同記事は「UIデザインとは別で、説明図解・資料に絞る」と述べているため、ここでは**画面の操作設計ではなく、ツールの見た目の仕上げ（配色・形・アイコン・余白）だけ**に適用しています。

- **雰囲気（3語）**: 落ち着いた／情報が主役／余白がある
- **配色**: 白背景＋アクセント1色（青）＋濃紺の文字。重大度・ペルソナ・要素種別のように、データの区別に必要な色だけを例外とする
- **形**: 角丸は2種（コンテナ10px／部品6px）、淡い枠線、影はごく薄い1種類のみ
- **文字**: 1書体（等幅はHTML貼り付け欄のみ）、太さは400と600、最小12px
- **アイコン**: 単色の線画（太さ1.75で統一）。絵文字は使わない
- **禁止**: グラデーション背景・絵文字・強い影・光沢・意味のない装飾
- **引き算のチェック**: 色数を数える／影を弱める／余白を足す／アイコンを揃える／フォントを絞る

変更前後の見た目を同じ基準で数えた結果（ツールの外枠とパネル。解析対象ページの内容は除く）:

| 指標 | 変更前 | 変更後 |
|---|---|---|
| 角丸の種類 | 8 | 3（10px・6px・円形） |
| 文字サイズの種類 | 8 | 5 |
| 文字の太さの種類 | 5 | 2 |
| 影の種類 | 2 | 1（ごく薄い） |
| 絵文字・記号で装飾した要素 | 23 | 0 |

## URL 解析用の中継（Cloudflare Workers の例）

```js
export default {
  async fetch(req) {
    const url = new URL(req.url).searchParams.get('url');
    if (!url || !/^https?:\/\//.test(url)) return new Response('bad url', {status: 400});
    const res = await fetch(url, {headers: {'User-Agent': 'Mozilla/5.0 UI-Anatomy-Scanner'}});
    const h = new Headers({'Access-Control-Allow-Origin': '*', 'Content-Type': 'text/html; charset=utf-8'});
    return new Response(await res.text(), {status: res.status, headers: h});
  }
};
```

アプリの「中継URL」に `https://<your-worker>.workers.dev/?url={url}` を入力します。公開運用する場合は、許可ドメインの制限とレート制限を入れてください。
