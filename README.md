# UI Anatomy Scanner（プロトタイプ）

UI の画面を入力すると、次の3つを一画面で確認できる分析ツールです。

1. **構成要素の抽出**: ボタン（主・副・テキスト・アイコン）、バナー、ナビゲーション、フォーム、カードなどの種類・数・位置
2. **ニールセン10ヒューリスティクスの指摘**: 根拠・重大度（0〜4）・改善案つき。補助としてWCAG由来のチェックも表示
3. **ペルソナ別の仮想ゲイズプロット**: ペルソナとタスクを選ぶと、想定される視線の順路・滞留・ヒートマップ・見落とされやすい要素を表示
4. **Before/After 比較**: 現在の解析結果を「Before」として保存し、別の画面（After）と同じ基準で比較。10原則スコアのレーダー重ね合わせ、解消・新規・変化した指摘、構成要素・Age Lens・仮想視線（30試行・同一シード）の差分を表示し、ステージ上では境界スライダーで左右に重ねて見られる。比較レポートは Markdown で書き出し
5. **ペルソナ並列比較**: 4ペルソナを同じ画面・タスクで同時にシミュレーションし、ワイヤーフレーム上の軌跡、指標（CTA到達率・到達時間・バナー注視率など）、要素×ペルソナの到達率マトリクス、ペルソナ間で見え方が分かれる要素の自動所見を並べる。ステージ上にも全員の軌跡を色と線種で重ねられる
6. **Age Lens**: 年齢・視覚特性のフィルタ（ぼやけ・コントラスト感度の低下・水晶体の黄変・視野狭窄・色覚特性）を画面に重ね、通常表示と左右で比較。レンズ適用後の見え方で「読みにくい文字」「押しにくい操作領域」「視野の外にある主要要素」「色の区別がつきにくくなるボタンの組み合わせ」を判定し、仮想視線にも反映できる

`index.html` を開くだけで動きます（単一HTML・ビルド不要）。

## 使い方

- **サンプル**: 架空の3サイト（EC／社内申請フォーム／SaaSランディング）。弱点を意図的に仕込んであります
- **HTML貼り付け**: ページのソースを貼ると解析します
- **URL**: ブラウザからは他サイトのHTMLを直接取得できない（CORS）ことが多いため、自前の中継を指定します（下記）

## 重要な制約（誤解を避けるために）

- 指摘は**ルールベースの推定**で、実ユーザーテストの代替ではありません。一次レビューを速くするための道具です
- 視線は**実測ではなく仮想**です。要素の目立ち・タスクとの関連・位置の傾向と、ペルソナごとの仮定から確率的に生成します（シード固定で再現可能）。重みはスライダーで変更できます
- スクリプトは実行しません（sandbox の iframe に HTML/CSS のみ描画）。JavaScript で描画されるサイトは、中身が少なく解析されることがあります
- ニールセン10項目のうち機械的に判定できるものだけ自動指摘し、判断が必要な項目は「要確認」として人が判定します

## 自動判定の対応表

| 原則 | 自動で見ているもの |
|---|---|
| H1 状態の視認性 | ステップ/ナビの現在地の有無と、強調の視覚差 |
| H2 実世界との一致 | 曖昧なリンク文言、英語混在、同義語の揺れ |
| H3 主導権と自由 | モーダルの閉じる手段、自動再生、カルーセルの停止、フォームの戻る導線 |
| H4 一貫性 | ボタンの見た目の種類数、角丸、フォント数、見出しサイズ |
| H5 エラー予防 | 破壊的操作と主要操作の近接、入力欄のtype |
| H6 認識>想起 | ラベルなしアイコン、プレースホルダのみの入力欄 |
| H7 柔軟性 | 検索の有無、autocomplete |
| H8 最小限のデザイン | ファーストビューのバナー数・主要ボタンの競合・操作要素の数 |
| H9 エラー回復 | エラー表示領域の有無 |
| H10 ヘルプ | ヘルプ/問い合わせ導線の有無 |
| 補助 | コントラスト比、小さな文字、操作領域の大きさ、alt |

## ペルソナ並列比較の注意

- 各ペルソナは既定の重み（目立ち・タスク関連・位置の傾向）で動かします。③のスライダーの値は使いません
- 30試行の平均と到達率は、同じ乱数列（シード固定）で計算するので、同じ設定なら同じ結果になります
- 「高齢者に④の設定を適用」を入れると、高齢者ペルソナだけ Age Lens の判定（読めない文字は注視されにくい）を反映します
- ペルソナ間の差は仮定の差から生まれる仮想の結果で、実ユーザーの行動を保証しません

## Before/After 比較の使い方と注意

- 使い方: 比較元の画面を解析 →「Beforeに保存」→ 別の画面（After）を解析 →「⑤ 比較」タブ。サンプルの「▶ Before/After デモ」で一連の流れを確認できます
- 指摘の対応づけ: 件数などの数字を除いたタイトル＋原則で同一の指摘とみなします（「ボタンの見た目が8種類」→「3種類」は『変化』）
- 仮想視線の比較は、両方の画面を同じペルソナ・タスク・乱数列で動かした差です。Age Lens の視線への反映は比較では使いません
- 差はルールベースの指標上の変化です。ユーザーにとって実際に良くなったかは、ユーザーテストで確認が必要です

## Age Lens の仕組みと注意

- 見た目: 解析対象を同じ内容でもう1枚描画し、CSS/SVGフィルタ（blur・contrast・色覚は Machado et al. 2009 の行列・黄変は青成分の減衰）を重ねて、左右で比較します
- 判定: 同じ変換を文字色・背景色に当ててコントラスト比を再計算し、WCAG の基準（通常文字4.5:1／大きな文字3:1）で判定します。ぼやけは文字サイズの約18%超で「重大」、約12%超で「注意」（経験則の目安・未検証）
- プリセット（65歳前後・白内障・緑内障など）の数値は**説明用の目安**です。医学的な再現や診断ではなく、実際の見え方は個人差が大きいです
- 背景が画像・グラデーションの文字は、背景色を一意に決められないため判定対象外（件数のみ表示）です

## URL 解析用の中継（Cloudflare Workers の例）

```js
export default {
  async fetch(req) {
    const url = new URL(req.url).searchParams.get('url');
    if (!url || !/^https?:\/\//.test(url)) return new Response('bad url', {status: 400});
    const res = await fetch(url, {headers: {'User-Agent': 'Mozilla/5.0 UI-Anatomy-Scanner'}});
    const h = new Headers({'Access-Control-Allow-Origin': '*', 'Content-Type': 'text/html; charset=utf-8'});
    return new Response(await res.text(), {status: res.status, headers: h});
  }
};
```

アプリの「中継URL」に `https://<your-worker>.workers.dev/?url={url}` を入力します。公開運用する場合は、許可ドメインの制限とレート制限を入れてください。

## 次の候補

- スクリーンショット入力（DOMが取れないサイト向け）と、画像からの要素検出
- ペルソナの自作（重みや視覚特性の組み合わせを保存）
- 3画面以上の比較（バージョン履歴）
- Age Lens の閾値を、文献や実ユーザー評価で較正する
- レポートのスライド用書き出し（課題設定→根拠→改善案の構成）
