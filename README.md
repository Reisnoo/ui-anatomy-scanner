# UI Anatomy Scanner（プロトタイプ）

UI の画面を入力すると、構成・原則・視線・見え方を一画面で確認できる分析ツールです。右パネルの7つのタブで構成されます。入力は、サンプル・URL・HTML貼り付けに加えて、**スクリーンショット（画像）**にも対応します。

1. **構成要素**: ボタン（主・副・テキスト・アイコン）、バナー、ナビゲーション、フォーム、カードなどの種類・数・位置
2. **10原則**: ニールセンの10ヒューリスティクスの指摘。根拠・重大度（0〜4）・改善案つき。補助として WCAG 由来のチェックも表示
3. **仮想視線**: ペルソナとタスクを選ぶと、想定される視線の順路・滞留・ヒートマップ・見落とされやすい要素を表示
4. **Age Lens**: 年齢・視覚特性のフィルタ（ぼやけ・コントラスト感度の低下・水晶体の黄変・視野狭窄・色覚特性）を画面に重ね、通常表示と左右で比較。レンズ適用後の見え方で「読みにくい文字」「押しにくい操作領域」「視野の外にある主要要素」「色の区別がつきにくくなるボタンの組み合わせ」を判定
5. **比較**: 「2画面（Before/After）」は、解析結果を「Before」として保存し、別の画面と同じ基準で比較（レーダーの重ね合わせ、解消・新規・変化した指摘、構成要素・Age Lens・仮想視線の差分、ステージ上の左右ワイプ、Markdown レポート）。「履歴（3画面以上）」は、画面を最大8件まで順に保存し、指標の推移・10原則スコアの変化・指摘の出入り・後退の検出を時系列で表示。JSON／共有リンクでの受け渡しと、**提出用レポート（単体HTML）** の書き出しができる
6. **ペルソナ**: 複数ペルソナの並列比較（ワイヤーフレーム上の軌跡・指標・要素×ペルソナの到達率マトリクス・自動所見）と、**ペルソナの自作**（視線の重み・ふるまい・視覚特性を保存）
7. **画面幅**: スマホ(375)・タブレット(768)・PC(1280)・ノートPC13インチ(1440)・大画面(1920)の画面幅で解析し、指摘・視線の違いを表で比べる。横はみ出し・タップ領域・メニューの折りたたみなどの画面幅の診断と、**直し方のコード例**つき

`index.html` を開くだけで動きます（単一HTML・ビルド不要）。

## 使い方

- **サンプル**: 架空の4サイト（EC／社内申請フォーム／SaaSランディング／ECの改善版）。弱点を意図的に仕込んであります。「Before/After デモ」で比較の流れを確認できます
- **HTML貼り付け**: ページのソースを貼ると解析します
- **画像（OCR）**: スクリーンショット（PNG・JPEG・WebP）を、選ぶ・貼り付ける（Ctrl/⌘+V）・ドロップして解析します。DOMが取れない画面（デザイン案・他社サイト・アプリ）向け。画像の中の文字・大きさ・色・ボタンの位置を推定します（下記「画像（OCR）入力」）
- **URL**: ブラウザからは他サイトのHTMLを直接取得できない（CORS）ことが多いため、自前の中継を指定します（下記）

## 重要な制約（誤解を避けるために）

- 指摘は**ルールベースの推定**で、実ユーザーテストの代替ではありません。一次レビューを速くするための道具です
- 視線は**実測ではなく仮想**です。要素の目立ち・タスクとの関連・位置の傾向と、ペルソナごとの仮定から確率的に生成します（シード固定で再現可能）
- スクリプトは実行しません（sandbox の iframe に HTML/CSS のみ描画）。JavaScript で描画されるサイトは、中身が少なく解析されることがあります。チャートなどJavaScriptで描かれる領域は、実際の画面とレイアウトが変わります
- 解析は、選んだ画面幅（既定は1280×800）の実際の表示のレイアウトで行います（`100vh`・固定サイドバーを含むページでも、全高で描いたときのずれの影響を受けません）。ステージ上の枠の位置が見えているページとずれる場合は、その旨を表示します。解析範囲の上限は12,000pxです
- ニールセン10項目のうち機械的に判定できるものだけ自動指摘し、判断が必要な項目は「要確認」として人が判定します

## 画像（OCR）入力

- **使い方**: 入力方法「画像（OCR）」で、スクリーンショットを選ぶ・貼り付ける（Ctrl/⌘+V）・ドロップします。言語（日本語＋英語／英語／日本語）と、画像の倍率（自動・1〜3倍。Retinaのスクリーンショットは2倍）を選べます。画像は、このブラウザの中だけで処理され、外部には送信されません。OCRエンジン（Tesseract.js 5.1.1）と言語データ（日本語・英語で約5MB）は、初回だけ CDN（jsDelivr）から取得して、ブラウザに保存します
- **やっていること**: ① 画像から文字の行を切り出し、背景に関係なく「白地に黒の文字」に直してOCRする（白抜き文字・色つき背景の文字も読める）② 行ごとに、文字の大きさ（全角は幅÷文字数、英数字は大文字の高さから）・文字色・背景色を推定する ③ 枠（ボタン・入力欄の候補）を、上下の辺の組から検出する ④ 結果から、文字・ボタン・見出し・ナビを画像と同じ位置に置いた再構成のHTMLを作り、既存の解析（構成要素・仮想視線・Age Lens・画面幅以外の指摘）にかける
- **指摘するもの**: DOMが取れないため、見た目から判定できる、コントラスト・小さな文字・操作領域・ファーストビューの操作数に限ります（リンクの意味・フォーム・見出しの構造・ニールセンの多くの項目は判定しません）。色の推定に誤差があるため、コントラストは基準の4%以内を「ぎりぎり合格」として指摘しません。文字サイズは、11.2px未満と推定したものだけを「12px未満」とします（11.2〜12pxは12pxとして扱う）
- **精度（実測。方法と全データは `validation/README.md`）**: 英語テンプレート30ページ（スクリーンショットとDOMを照合。仕組みの調整には使っていないが、一部の設定は結果を見たあとで決めたため、完全な未見ではない）で、文字の行の検出率 90〜94%・文字の誤り率 3〜5%、文字サイズの推定は中央値で誤差 1〜2%（±15%以内 98%）、コントラストが基準未満かの判定は、基準ぎりぎりを除くと適合率100%・再現率88〜97%。日本語の自作5ページでは検出率97%・誤り率1%（ただし、この5ページは調整に使ったため、参考値）。従来の「ページ全体を一度に読む」方式は、開発セットで検出率78%・誤り率14.5%だった
- **限界**: 写真・グラデーション・半透明の上の文字は、読み取れないことがある／ボールド・斜体・書体は推定しない／1行に大きさの違う文字が混ざる場合は、行の代表値になる／縦書き・回転した文字・文字が極端に小さい（約8px未満）画像は対象外／スクリーンショットの圧縮（JPEG）で、色の推定が乱れる／ボタン・入力欄の候補は、枠が見えるものだけ（枠のない文字だけのリンクや、アイコンだけのボタンは判別できない）で、**精度は低め**（未見に近い30ページで、再現52〜76%・適合率63〜67%。表のセル・バッジの取り違えや、入力欄の薄い文字の読み落としがある）。処理は、1280×3000pxの画像で約4秒（端末による）。画像が長い場合は、先頭8,000px（CSS換算）までを解析します

## 画面幅（レスポンシブ）の見方

- 入力欄の下の「解析する画面幅」で、スマホ(375×812)・タブレット(768×1024)・PC(1280×800、既定)・ノートPC13インチ(1440×900)・大画面(1920×1080)・カスタムを切り替えます。切り替えると、その幅で再解析し、ステージの表示・指摘・仮想視線が変わります。ノートPCは MacBook 13インチの標準的な表示（1440×900）で、Windowsの小型ノートは1366×768が多いため、カスタムで指定してください
- ⑦「画面幅」の「5つの画面幅で比べる」で、5つの幅を順に解析して、要素数・指摘・横はみ出し・操作領域の最小・文字の最小・主要ボタン(CTA)がファーストビューに入るか・CTAへの視線の到達率を表にします。幅によって出たり消えたりする指摘も一覧できます。視線は、選択中のペルソナ・タスクの仮想の結果です（実測ではありません）
- 画面幅の診断（解析幅に応じて出る指摘）: 横方向のはみ出し／viewport メタタグの有無とピンチ拡大の禁止／操作領域44px未満（〜1024px）／入力欄が16px未満（スマホ、iOSの自動拡大）／ナビが折りたたまれていない（スマホ）／固定帯が画面を占める割合（スマホ）／画面幅別のCSSがない／本文の1行が長すぎる（1280px以上）
- **修正のコード例**: 画面幅の指摘と、コントラスト・小さな文字・操作領域・alt・アイコンのみのボタン・ラベルなし入力欄・autocomplete・現在地・エラー表示などの指摘に、「修正の書き方（コード例）」を付けます。コントラストは、背景を変えずに基準（4.5:1／大きな文字3:1）を満たす最小限の文字色を、実際の値から計算して示します。Markdownレポートにも入ります。コード例は出発点で、実際のページの構造・デザインに合わせた調整が必要です
- 限界: ブラウザの実機（実際のスマホ）ではなく、同じ幅の枠でレイアウトを再現した結果です。`viewport` メタタグの効果（スマホが約980px幅で描く挙動）・端末のピクセル比・ブラウザごとの違い・タッチ操作は再現しません。メディアクエリの有無は、同じドメインで読める（インラインや同一オリジンの）CSSだけで確認し、外部CSSが読めないときは判定しません。仮想視線は、幅によらず同じ重みで動かしているため、スマホ特有の見方（スクロール中心の閲覧など）は反映していません

## 提出用レポート（単体HTML）

「⑤ 比較」→「履歴」の下部「提出用レポート」から、履歴を**外部ファイルなしの1つのHTML**に書き出せます（ポートフォリオの補足資料として添付する用途）。`examples/sample-history-report.html` が、デモデータで作ったサンプルです。

- **内容**: 要約（4つの数値と自動の所見）、目的・課題設定と設計判断（入力した場合）、分析した画面の一覧とスナップショット（任意）、8指標の推移グラフ、10原則スコアのヒートマップ、指摘の出入り、分析の条件（ペルソナ・タスク・Age Lensの設定）、方法と限界、このツールの検証状況、自動判定の対応表
- **入力欄**: タイトル、作成者、目的・課題設定（400字）、設計判断・補足（600字）。面談で言われた「課題設定と、デザイン選定の理由を言語化して添える」ための欄です。内容はこのブラウザに保存されます
- **単体で開ける**: グラフはインラインSVG、スタイルも同じファイルに入っています。外部へのリクエストはありません（スナップショットを載せた場合、その画面が参照する外部の画像・CSSは、開く環境で読み込めないことがあります）
- **印刷・PDF**: A4・余白16mmの印刷用スタイルつき。ブラウザの「印刷」→「PDFに保存」で、6ページ前後のPDFになります
- **安全性**: 入力した文字は、すべてエスケープして出力します。スナップショットは、スクリプトを実行しない隔離した枠に入れます
- **注意**: スナップショットを載せると、解析した画面の中身（HTML）がレポートに入ります。社外秘の画面では、載せないでください（既定はオフ）

## ペルソナの自作

「⑥ ペルソナ」→「作る・編集する」で作成します。

- **視線のふるまい**: 視覚的な目立ち／タスク関連／位置の傾向の重み、注視の回数と長さ、視線の移動距離、見返しやすさ、本文を読む傾向、バナーへの反応
- **視覚特性**: ④ Age Lens と同じ指標（ぼやけ・コントラスト感度・黄変・視野狭窄・色覚）。プリセットからのコピーや、④の現在の設定の取り込みもできる。視覚特性があるペルソナは、読めない文字の要素が注視されにくくなる
- 標準の4ペルソナは編集できず、選ぶと「コピー」として編集できます。自作は最大6件
- 保存先はこのブラウザの localStorage です（端末をまたいで共有されません）。JSON で書き出し・読み込みができるので、バックアップや別端末への移行はこちらを使います
- 比較に含めるペルソナは、「比較する」画面のチップで切り替えます

## バージョン履歴の使い方と注意

- 使い方: 画面を解析して「履歴に追加」を、改善の節目ごとに繰り返します（最大8件）。サンプルの「デモを開く」で、ECストアの4段階の改善（V3には後退を1つ仕込んであります）を確認できます
- 表示: 8つの指標の推移グラフ、10原則スコアのヒートマップ（直前との差つき）、指摘の出入りの表（解消・再発・残存）、自動の所見（後退したバージョン・原則、再発、最後に残る指摘）
- バージョンは名前の変更、上下の並べ替え、削除ができます。「ステージに重ねる」で、そのバージョンと現在の画面を左右で見比べられ、「Beforeにする」で2画面比較に切り替えられます
- 全バージョンの仮想視線とAge Lensの値は、③④で選んでいる設定（ペルソナ・タスク・レンズ）にそろえて、保存済みのデータから再計算します
- 保存先はこのブラウザ（localStorage）です。容量が足りないときは保存できず、タブを開いている間だけ使えます。保存されるのは解析結果と画面のHTMLで、画像などの外部ファイルは含みません
- 推移はルールベースの指標の変化です。ユーザーにとって実際に良くなったかは、ユーザーテストで確認が必要です

### 履歴の書き出し・読み込み・共有（端末をまたぐ）

サーバーを持たない静的サイトなので、次の2つの方法で受け渡します。

- **JSONファイル**: 「JSONファイルに書き出す」「ファイルから読み込む」（または貼り付け）。読み込み方は「後ろに追加」か「置き換え」を選べます（合計8件まで）。バックアップや別端末への移行はこちらが確実です
- **共有リンク**: 履歴を圧縮してURLの `#share=…` に入れます。`#` 以降はブラウザからサイトのサーバーに送信されません。ただしデータが多いと長くなり（ECデモの4件で約9,000文字）、チャットやメールで途中で切れることがあります。リンクで開くと「共有された履歴を受け取りました」と表示され、追加・置き換え・破棄を選べます（勝手に上書きしません）
- **含める内容**: 既定は解析結果の数値だけです。「画面のHTMLを含める」を入れるとステージの重ね表示もできますが、解析した画面の中身も相手に渡るため、社外秘の画面では入れないでください。「自作ペルソナを含める」で、ペルソナも一緒に渡せます（同じ内容のペルソナは重複して追加しません）
- **安全性**: 外部から来たデータは信頼せず、形式・種類・数値の範囲・文字数を検証し、不正な項目は捨ててから取り込みます。画面のHTMLはスクリプトを実行しない隔離した枠でしか表示せず、ラベルなどの文字列はエスケープして表示します。ファイルは8MBまで、展開後が大きすぎる共有リンクは拒否します
- 共有リンクの生成・読み込みには、ブラウザの圧縮機能（CompressionStream）が必要です。使えないブラウザでは、ファイルを使ってください

## 比較機能の注意

- **Before/After**: 指摘は、件数などの数字を除いたタイトル＋原則で同一とみなします（「ボタンの見た目が8種類」→「3種類」は『変化』）。仮想視線は、両方の画面を同じペルソナ・タスク・乱数列で動かした差で、Age Lens の視線への反映は使いません。差はルールベースの指標上の変化で、実際に良くなったかはユーザーテストで確認が必要です
- **ペルソナ並列比較**: 各ペルソナは、そのペルソナ自身の重みで動かします（③のスライダーの値は使いません）。30試行は同じ乱数列なので、同じ設定なら同じ結果になります。差は仮定の差から生まれる仮想の結果で、実ユーザーの行動を保証しません

## Age Lens の仕組みと注意

- 見た目: 解析対象をもう1枚描画し、CSS/SVGフィルタ（blur・contrast・色覚は Machado et al. 2009 の行列・黄変は青成分の減衰）を重ねて、左右で比較します
- 判定: 同じ変換を文字色・背景色に当ててコントラスト比を再計算し、WCAG の基準（通常文字4.5:1／大きな文字3:1）で判定します。ぼやけは文字サイズの約18%超で「重大」、約12%超で「注意」（経験則の目安・未検証）
- プリセット（65歳前後・白内障・緑内障など）の数値は**説明用の目安**です。医学的な再現や診断ではなく、実際の見え方は個人差が大きいです
- 背景が画像・グラデーションの文字は、背景色を一意に決められないため判定対象外（件数のみ表示）です

## ツール自体のデザイン方針（固定スペック）

「AI が作った感」を避けるため、「ほしい雰囲気」と「避けたい表現」をセットで固定しています。考え方は、Fyve「[AIで作る図解のAI感を消す方法｜プロンプト設計](https://fyve.co.jp/ai-advisor/articles/ai-diagram-remove-ai-look)」（2026/07/25）を参考にしました。ただし同記事は「UIデザインとは別で、説明図解・資料に絞る」と述べているため、ここでは**画面の操作設計ではなく、ツールの見た目の仕上げ（配色・形・アイコン・余白）だけ**に適用しています。

- **雰囲気（3語）**: 落ち着いた／情報が主役／余白がある
- **配色**: 白背景＋アクセント1色（青）＋濃紺の文字。重大度・ペルソナ・要素種別のように、データの区別に必要な色だけを例外とする
- **形**: 角丸は2種（コンテナ10px／部品6px）、淡い枠線、影はごく薄い1種類のみ
- **文字**: 1書体（等幅はHTML貼り付け欄のみ）、太さは400と600、最小12px
- **アイコン**: 単色の線画（太さ1.75で統一）。絵文字は使わない
- **禁止**: グラデーション背景・絵文字・強い影・光沢・意味のない装飾
- **引き算のチェック**: 色数を数える／影を弱める／余白を足す／アイコンを揃える／フォントを絞る

変更前後の見た目を同じ基準で数えた結果（ツールの外枠とパネル。解析対象ページの内容は除く）:

| 指標 | 変更前 | 変更後 |
|---|---|---|
| 角丸の種類 | 8 | 3（10px・6px・円形） |
| 文字サイズの種類 | 8 | 5 |
| 文字の太さの種類 | 5 | 2 |
| 影の種類 | 2 | 1（ごく薄い） |
| 絵文字・記号で装飾した要素 | 23 | 0 |

## 精度確認

自動判定が実在のページでどのくらい正しいかを、axe-core との照合で測っています。要点だけ書きます。詳しい方法・数値・見つかった問題・残る限界は [`validation/README.md`](validation/README.md) を見てください。

- 実在のオープンソーステンプレート45ページ（MIT）で測定。**修正後に初めて走らせた未見14ページ**で、コントラスト不足の検出は再現率96%・適合率100%、ボタン名の検出は再現率91%
- 最初の測定（修正前）では、同種の未見ページで再現率が48%にとどまり、原因（レイアウトを実際と違う高さで描いていた等）を直した。その過程も記録している
- **ニールセン10原則の指摘の妥当性は、まだ測れていない**（外部ツールに正解がなく、人手の採点が必要。採点シートと集計スクリプトは用意済みで、採点は未実施）
- 対象はBootstrap系の英語テンプレートが中心で、**ライブのWebサイトではない**。実サイトの測定は、自分のPCで `node run.js --live urls.txt` を使う

## URL 解析用の中継（Cloudflare Workers の例）

```js
export default {
  async fetch(req) {
    const url = new URL(req.url).searchParams.get('url');
    if (!url || !/^https?:\/\//.test(url)) return new Response('bad url', {status: 400});
    const res = await fetch(url, {headers: {'User-Agent': 'Mozilla/5.0 UI-Anatomy-Scanner'}});
    const h = new Headers({'Access-Control-Allow-Origin': '*', 'Content-Type': 'text/html; charset=utf-8'});
    return new Response(await res.text(), {status: res.status, headers: h});
  }
};
```

アプリの「中継URL」に `https://<your-worker>.workers.dev/?url={url}` を入力します。公開運用する場合は、許可ドメインの制限とレート制限を入れてください。
